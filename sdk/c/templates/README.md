# Matrix C/C++ node: <NAME>

Generated by `scaffold.sh` (ML1, `@CXX@` = 1 means the C++ node).
Generic test component speaking `matrix.component/0.1`: echo, chained
dependency calls, resources, streams, events, cancel. Same contract as
`docs/ML1-NODE.md`; no product application. SDK sources are vendored
(`src/`, `include/`, plus `cpp/` for C++); the build needs only CMake
plus a C11 (and for C++, C++17) compiler — no network, no packages.

## Layout

- `node.c` / `node.cpp` — the component (`cmake -B build && cmake
  --build build`).
- `src/` + `include/` (+ `cpp/matrix.hpp` for C++) — vendored SDK.
- `config.json` — managed-service config template (fill in paths and
  the operator fingerprint, then serve).
- This README — the recipe.

## 1. Build (offline)

```sh
cmake -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build
ctest --test-dir build   # SDK self-tests (component, operator, C++)
```

## 2. Configure the operator (authority lives here, not in the node)

Edit `config.json`: private `home`, one component entry per logical
id (`prov`, `cons`, `indep`) with entrypoint `./build/mx-node` (or
`mx-node-cpp` for `--cxx`), `grants` mapping the operator certificate
fingerprint (`matrix-managed fingerprint pki/client.der`) to
components and capabilities, explicit `outbound_grants` for consumers
(requested is never granted), and `tls` (dev PKI via
`scripts/dev-pki.py` of the Matrix repo; never weaken mTLS for demos).

## 3. Serve and compose

```sh
/path/to/matrix-managed serve config.json
```

Or from C (no CLI quoting):

```c
mx_op_kernel_t *k = NULL;
char *err = NULL;
mx_op_start("/path/to/matrix-managed", cfg_path, ca, cert, key,
            "localhost", &k, &err);
mx_op_client_t *c = mx_op_kernel_client(k);
char *resp = NULL;
mx_op_request(c, "{\"action\":\"activate\",\"component\":\"prov\","
                 "\"ttl_ms\":20000}", 30000, &resp, NULL, NULL);
/* ... invoke ... */
mx_op_kernel_close(k); /* owned: reaps only this daemon */
```

`mx_op_connect()` instead of `mx_op_start()` attaches to a shared
kernel; closing the attachment never stops it.

## 4. Test and withdraw

- Ungranted capability or bad lease: denied with a stable code
  (`permission-denied`, `stale-generation`), never dispatched.
- Withdraw: `release` the lease, remove/re-provision the component
  (new generation, old refs stay dead), re-`activate`.
- Crash path: kill the node process mid-`sleep_ms` call; the invoke
  terminal is not-ok and re-issuing the same operation never
  auto-replays an unknown effect.

## 5. Cleanup

Stop the daemon (SIGTERM/SIGINT; owned kernels via
`mx_op_kernel_close()`), remove the private `home` directory. Leases
are credentials: do not paste them into reports.

## 6. Diagnose

```sh
./build/matrix-doctor --binary /path/to/matrix-managed
```

(Environment diagnosis as JSON; paths point at the SDK checkout or
staged copy. The C++ SDK shares the C transport: one `matrix-doctor`
covers both, and `docs/ML1-MATRIX.md` records the split.)
