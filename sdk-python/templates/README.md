# Matrix Python node: <NAME>

Generated by `scaffold.sh` (ML1). Generic test component speaking
`matrix.component/0.1`: echo, chained dependency calls, resources,
streams, events, cancel. Same contract as `docs/ML1-NODE.md`; no
product application.

## Layout

- `node.py` — the component (run one process per logical id).
- `config.json` — managed-service config template (fill in paths and
  the operator fingerprint, then serve).
- This README — the recipe.

## 1. Install the SDK (isolated, offline)

```sh
python3 -m venv .venv
.venv/bin/pip install --no-index /path/to/matrix_kernel-*.whl
```

`node.py` imports `matrix_component` (installed) for the wire
protocol and `matrix_operator` for the operator surface. No `PYTHONPATH`
tricks: the wheel is the install.

## 2. Configure the operator (authority lives here, not in the node)

Edit `config.json`:

- `home`: a private directory for this service instance.
- `components`: entrypoint `node.py` with your venv python, one entry
  per logical id (`prov`, `cons`, `indep` below).
- `grants`: map the operator certificate fingerprint
  (`matrix-managed fingerprint pki/client.der`) to components and
  capabilities. Requested (`outbound.request`) is never granted: add
  `outbound_grants` explicitly for consumers.
- `tls`: dev PKI via `scripts/dev-pki.py` of the Matrix repo (or your
  own CA); never weaken mTLS for demos.

Generate dev PKI + fingerprint:

```sh
python3 /path/to/dev-pki.py pki --server-name localhost
/path/to/matrix-managed fingerprint pki/client.der
```

## 3. Serve and compose

```sh
/path/to/matrix-managed serve config.json
```

In another shell (replace `$FP` with the fingerprint, `$LISTEN`
with the ready line address):

```sh
M=path/to/matrix-managed; P=pki
L=$($M request $P/ca.der $P/client.der $P/client-key.der $LISTEN localhost \
  '{"action":"activate","component":"prov","ttl_ms":30000}')
TOK=$(echo "$L" | python3 -c "import json,sys; print(json.load(sys.stdin)['lease'])")
FN=$(echo "$L" | python3 -c "import json,sys; print(json.load(sys.stdin)['fence'])")
$M request $P/ca.der $P/client.der $P/client-key.der $LISTEN localhost \
  "{\"action\":\"invoke\",\"lease\":\"$TOK\",\"fence\":\"$FN\",\"operation\":\"op-1\",\"cap\":\"prov.echo@1\",\"input\":{\"chain\":true,\"input\":{\"value\":11}}}"
```

Or drive the same flow from Python (no CLI quoting):

```python
from matrix_operator import start
kernel = start("/path/to/matrix-managed", config_dict, operator_pki)
act = kernel.client.activate("prov", 30000)
v = kernel.client.invoke(act["lease"], act["fence"], "op-1",
                         "prov.echo@1", {"ping": 1})
kernel.close()  # owned: reaps only this daemon
```

`connect()` instead of `start()` attaches to a shared kernel;
closing the attachment never stops it.

## 4. Test and withdraw

- Ungranted capability or bad lease: denied with a stable code
  (`permission-denied`, `stale-generation`), never dispatched.
- Withdraw: `release` the lease, remove/re-provision the component
  (new generation, old refs stay dead), re-`activate`.
- Crash path: kill the node process mid-`sleep_ms` call; the invoke
  terminal is not-ok and re-issuing the same operation never
  auto-replays an unknown effect.

## 5. Cleanup

Stop the daemon (SIGTERM/SIGINT; owned kernels via
`kernel.close()`), remove the private `home` directory and scratch
venvs. Leases are credentials: do not paste them into reports
(`matrix-doctor` redacts).
